### Proposta de política de navegador mínimo (para o dono decidir)
Hoje nada escrito diz qual é o navegador mínimo, e o `@vitejs/plugin-legacy` define a fronteira sozinho: quem tem `import.meta.resolve` (Chrome/Edge 105+, Firefox 106+, Safari 16.4+) recebe o pacote moderno SEM polyfill; quem não tem recebe o legado (polyfill por uso, alvo `defaults, not IE 11`). Proposta: **Chrome/Edge 109 e Firefox ESR 115 como piso declarado** (são os últimos do Windows 7/8.1), com três consequências práticas: (1) API mais nova que isso no código da casa só com guarda (a varredura de hoje achou o código da casa limpo); (2) dependência que use API mais nova num caminho alcançável ganha o ponto único com polyfill guardado (precedente: `vendor/shpjs.js`); (3) um censo que varra o `dist/` moderno contra a lista de APIs pós-piso, como o script desta caça, para a próxima dependência não entrar calada. CSS: `:has()` (Firefox 121) já é usado em 16 regras e cai inteiro no ESR 115 (cosmético hoje; pior caso: uma lista de seletores com `:has()` derruba também o seletor válido do lado, como em `sidebar.css` `.unified-attributes-panel`).
